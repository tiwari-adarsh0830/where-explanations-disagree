Does the answer depend on how you patch?

Activation patching is not one measurement. Each column is a different way of doing it: noising (swap a head's output for its output on a corrupted prompt) or denoising (put a head's clean output back into a corrupted run), with three-new-names (ABC) corruption, a name flip, or the average over corrupted prompts, at all positions or the final token only. Each cell says how well the row agrees with that column, as Spearman ρ on |score| over the 144 heads (or top-10 overlap), for the prompts in the Name order filter. Click a column to make it the reference for every other view. Attribution patching is a gradient estimate of the first column, so it has a built-in advantage there.

Do groups of heads behave like their parts?

Each bar is the drop in logit(IO) − logit(S) when a whole group of heads is patched with its corrupted output at the same time, with a 95% bootstrap interval over prompts. The tick is what you would predict by adding up the effects of patching each head on its own. A positive value means the model gets worse at the task. The three panels split the prompts by name order; the one matching the Name order filter is outlined.
