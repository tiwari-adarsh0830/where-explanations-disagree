Where Explanations Disagree

GPT-2 small on indirect object identification (IOI). Four ways of scoring the 144 attention heads, compared with activation patching: the drop in logit(IO) − logit(S) when a head's output is replaced by its output on a corrupted prompt with three fresh names.

Start here what this page is, the terms, and the three findings

The question

Four common ways of scoring how much each attention head matters often disagree. Activation patching is the experiment: replace one head's output with its output on a corrupted prompt and see how much the answer changes. This page checks each score against patching, shows that patching itself can be done several ways, and explains, head by head, why the scores disagree.

Findings, live from the data below

    Terms

    Head
    One of the 144 attention heads (layer.head, e.g. 5.5).
    Score / method
    A way to rate a head: attention, direct logit attribution (DLA: the head's direct push on the answer), attribution patching (a gradient estimate of patching).
    Noising
    Run the clean prompt, swap in one head's corrupted output: is the head necessary?
    Denoising
    Run the corrupted prompt, put back one head's clean output: is the head sufficient?
    Corruption
    The altered prompt used for patching (new names, a name swap, a changed year…).
    Agreement
    Spearman rank correlation of |score| with |patching effect| over the 144 heads (1 = same order).
    Baseline
    A score that knows nothing about the task (layer number, head activity): agreement any score gets for free.
    Assumption check
    A separate experiment testing what a score must assume to match patching.

    Why do the methods disagree about this head?

    Each method measures something narrower than “how important is this head”, and matches patching only if one assumption holds. Each row tests that assumption with a separate intervention, so a disagreement comes with its reason and the experiment behind it. The checks use the default patching setting (). A violation near 0 means the assumption holds for this head, near 1 means it breaks.

    Which heads change each other's effect?

    Single-head patching assumes a head's effect does not depend on the others. Each cell patches two of the most important heads together and compares that with their two single effects added: interaction = together − (first + second). Blue: patched together the change is above the sum; red: below it. What that means depends on the two heads. If both push toward the right answer, blue means each covers for the other (backup) and red means they sit on the same pathway, so removing one already removes part of the other's effect; for two heads that both push against it (negative name movers) it is the other way round. If one helps and the other hurts, the cell only says that one head's effect depends on the other. The tooltip and the pinned pair spell out which case applies. Click a cell to pin the pair and select its row head.

    Where does the selected head look?

    The selected head's attention, averaged over the 4 prompts of one template and name order (each row is a query token and sums to 100%). Names are shown by role: S1 and S2 are the two mentions of the subject, IO is the right answer. Other words come from one example prompt; places and objects vary between the 4. Outlined cells are the six positions we score heads at, and the thick outline is this head's best one over all prompts. Value-weighted scales each entry by how much that token actually writes into the output (Kobayashi et al. 2020).

    Does the answer depend on how you patch?

    Activation patching is not one measurement. Each column is a different way of doing it: noising (swap a head's output for its output on a corrupted prompt) or denoising (put a head's clean output back into a corrupted run), with three-new-names (ABC) corruption, a name flip, or the average over corrupted prompts, at all positions or the final token only. Each cell says how well the row agrees with that column, as Spearman ρ on |score| over the 144 heads (or top-10 overlap), for the prompts in the Name order filter. Click a column to make it the reference for every other view. Attribution patching is a gradient estimate of the first column, so it has a built-in advantage there.

    Do groups of heads behave like their parts?

    Each bar is the drop in logit(IO) − logit(S) when a whole group of heads is patched with its corrupted output at the same time, with a 95% bootstrap interval over prompts. The tick is what you would predict by adding up the effects of patching each head on its own. A positive value means the model gets worse at the task. The three panels split the prompts by name order; the one matching the Name order filter is outlined.
